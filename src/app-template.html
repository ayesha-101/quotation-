Not built yet — needs the real backend
  • Snyk MCP. Scans dependencies for known vulnerabilities. This app has none today (single static file, no packages) — becomes essential once the real backend has a package.json.
  • Malware scanning on uploaded customer LPO files. Snyk does not cover this — it scans source code and dependencies, not arbitrary uploaded documents. Today the customer LPO upload keeps only the filename and size as an audit record; the file's actual bytes are never stored or transmitted, specifically because there is no backend yet to safely receive and scan them. A real deployment needs a proper file-scanning service (e.g. ClamAV or VirusTotal) sitting behind the upload endpoint, quarantining any file until it's confirmed clean before it touches storage.
  • Blockchain anchoring of the audit chain. The hash chain above proves internal consistency as shipped, but runs entirely client-side with no independent witness — it doesn't stop someone with devtools access from regenerating a whole new consistent chain. The real fix: the backend batches new chain records periodically (e.g. hourly), computes one Merkle root over the batch, and anchors that root hash — never any actual quotation or customer data — to a public blockchain via OpenTimestamps (Bitcoin-anchored, free, purpose-built for this). Anyone can then verify a batch existed at or before a given time without trusting BMTC's server at all.
  • System-wide PII masking. Masking now covers actor/action text entering the audit chain (emails, phone numbers). Customer names/contacts in exports and the future Zoho/SAP integration layer still flow unmasked.
  • Continuous monitoring. This review is a point-in-time snapshot. A real deployment re-runs it on every change (CI-gated), not on request.
