# quotation-

## OpenSpec

This repo uses [OpenSpec](https://github.com/Fission-AI/OpenSpec) for spec-driven
development: you plan a change as reviewable artifacts (proposal, specs, design,
tasks) before any code is written, then implement against them.

The workflow is installed as Claude Code skills in `.claude/skills/` with matching
slash commands in `.claude/commands/opsx/`. Both are generated by the OpenSpec CLI
(`openspec init --tools claude`) — don't edit them by hand; re-run
`openspec update` to pick up new versions.

### Prerequisites

The skills drive the `openspec` CLI, so install it first:

```bash
npm install -g @fission-ai/openspec
```

### Workflow

| Command | Skill | What it does |
| --- | --- | --- |
| `/opsx:explore` | `openspec-explore` | Think through an idea before committing to a plan |
| `/opsx:propose` | `openspec-propose` | Create a change and generate all planning artifacts |
| `/opsx:update` | `openspec-update-change` | Revise a change's artifacts and keep them coherent |
| `/opsx:apply` | `openspec-apply-change` | Implement the change's tasks |
| `/opsx:sync` | `openspec-sync-specs` | Fold delta specs into the main specs without archiving |
| `/opsx:archive` | `openspec-archive-change` | Finalize a completed change and update specs |

Typical cycle:

```text
/opsx:propose "add quotation export"   → openspec/changes/add-quotation-export/
/opsx:apply                            → implements the tasks
/opsx:archive                          → openspec/changes/archive/<date>-add-quotation-export/
```

### Project config

`openspec/config.yaml` selects the workflow schema (`spec-driven`) and is where you
add project context, per-artifact rules, and per-operation guidance that OpenSpec
passes to the AI when generating artifacts.
